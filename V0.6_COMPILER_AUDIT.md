# v0.6 Compiler Audit — `chatgpt_executable_handoff_v2.0` against v0.5

## Verdict

The uploaded handoff package was useful, but not because v0.5 needed another architecture/specification pass. v0.5 already satisfied most of its pipeline in substance. The valuable missing layer was **explicit compilation and traceability between closed product meaning, actual bytes, evidence, and reality gates**.

## What was already present in v0.5

- **Product Authority Compiler:** horizons, objects/states/flows, scenario atlas, UX/copy, decision ledger and source closure were already strong enough to prevent downstream reinterpretation.
- **Solution/Prefab Build:** the whole local product already existed; `WHOLE_PRODUCT` was the correct mode.
- **QA/Evidence:** executable unit/integration/browser/temporal canaries and release evidence already existed.
- **Reality Probe / Thin Executor:** local release classification and one-command real-Voice finalization already kept downstream work bounded.
- **Context State:** `QA_STATE.yaml`, task DAG and execution intake already preserved active state without requiring chat-history reconstruction.

## What the compiler exposed as genuinely missing

### 1. Artifact registry semantics
v0.5 had a file manifest but no logical artifact IDs binding **fingerprint + implemented scenarios + evidence + known limits**. v0.6 adds `ARTIFACT_CATALOG.json` → `ARTIFACT_REGISTRY.json`.

### 2. Scenario-to-proof completeness
The scenario atlas was richer than the executed evidence map. v0.6 classifies all 40 scenario/cross-factor cases and refuses to equate “implemented” with “proven.”

### 3. Candidate identity as a single authority
v0.5 repeated version/candidate constants across runtime/export/release/manifest/UI. v0.6 centralizes runtime identity in `voice_proto/version.py` and checks active surfaces for stale identity.

### 4. A package-level acceptance compiler
v0.5 had several correct validators but no one operation that checked product closure → identity → artifacts → traceability → executable QA → local release. v0.6 adds `scripts/final_acceptance.py`.

## Product defects found because of the stronger compiler

The comparison produced concrete behavior changes rather than only governance files:

- invalid numeric edits violated SCN-010 by silently clamping/retaining invalid local state; fixed with inline rejection + prior-value preservation;
- Add Event violated SCN-006 by auto-placing after the existing score; fixed to authority-defined `0 ms`;
- Duplicate Event violated SCN-007 by adding `+250 ms`; fixed to exact timing/processing duplication;
- dirty Delete lacked the SCN-009 confirmation condition; fixed and canary-protected.

Additional direct proofs were added for atomic-write failure, pitch-shift semantics, deterministic same-score rerun, research-note binding, play-from-selection, disabled-event exclusion and full stop cleanup.

## What was deliberately not imported

The handoff's generic validation-domain list and abstract compiler wording were not turned into extra product phases. This project is a static/artistic + research/procedural local application; full-stack/mobile validation modes would add ceremony without evidence. The working v0.5 architecture was retained.

## Result

v0.6 is closer to the purpose the handoff package was meant to enforce: ChatGPT has done the interpretation, construction, correction and validation work; a lighter downstream model is left with bounded target execution and evidence-backed repair only.
